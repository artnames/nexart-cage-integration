# NexArt ↔ Google CAGE Conformance Evidence

Status: **PASS**

Evidence baseline: **17 September 2026**

This repository contains the validation evidence for interoperability
between NexArt and the Google CAGE `provider_02` integration boundary.

The validation treats NexArt as an execution-evidence layer:
cryptographically binding accepted execution evidence into independently
verifiable Certified Execution Records (CERs).

## Fail-closed behaviour

The test programme intentionally supplied malformed, conflicting and
tampered evidence.

NexArt rejected cases including:

- missing parents
- future parents
- self parents
- duplicate parents
- unknown nodes
- invalid step UUIDs
- invalid parent UUIDs
- concrete execution cycles
- terminal-path mismatches
- conflicting mutation of an existing execution identity
- modifications to protected CER evidence

Rejected evidence was not silently normalised into conformant evidence.

## Independent cryptographic verification

Stage 08 independently verified:

- CER certificate hashes
- NexArt receipt Ed25519 signatures
- NexArt verification-envelope Ed25519 signatures
- receipt-to-certificate binding
- protected evidence integrity

Four frozen CERs were mutated across four protected evidence categories:

- `signals`
- `metadata`
- `stateHash`
- `parentStepIds`

All 16 negative tamper controls were detected.

## CAGE HITL compatibility

The tested CAGE HITL path is not currently production-conformant.

The unchanged CAGE adapter output exposed two upstream compatibility
gaps:

1. the synthetic `hitl_interrupt` step contains an empty `stateHash`
2. `hitl_interrupt` is emitted by the adapter but is absent from the
   supplied finance topology

After isolating the `stateHash` syntax defect on a diagnostic copy,
NexArt also detected:

- `UNKNOWN_NODE`
- `ILLEGAL_EXECUTED_EDGE`

The subsequent `governed_trader` step was also observed not to reference
the synthetic HITL step in `parentStepIds`.

NexArt validation was not weakened to accept this evidence.

The HITL fixture was not submitted to production.

## What this evidence establishes

For the tested CAGE `provider_02` path, valid execution evidence can be:

1. generated by the CAGE adapter
2. validated against execution-structure rules
3. cryptographically bound into NexArt CERs
4. persisted by the production NexArt Node
5. independently verified
6. detected as modified when protected evidence changes

This establishes production interoperability for the tested CBF path.

## Explicit non-claims

This conformance evidence does not claim that NexArt independently proves:

- that an execution occurred exactly as represented in the external world
- that producer-supplied facts were truthful
- the private preimage represented by `stateHash`
- CAGE producer identity where no typed producer-authentication evidence exists
- policy correctness
- model correctness
- safety
- legal or regulatory compliance

NexArt proves integrity and authenticity of the evidence it accepts and
attests within the tested cryptographic model.
